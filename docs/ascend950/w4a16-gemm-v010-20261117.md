# W4A16 GEMM performance & contract qualification — 2026-11-18

## Result and qualification

The integrated Ascend 950 `GEMMW4A16FwdOp` implementation passes all **15 manifest cases**
with full-output verification, original numerical tolerances, negative controls, and input
preservation. Against the audited **same-process vendor baseline** on the canonical runner —
`torch_npu.npu_weight_quant_batchmatmul` over transposed `npu_convert_weight_to_int4pack`
weights, scales, offsets, and group size — all **15 ratios exceed the 0.8 threshold**; the
minimum is **0.902266** (`decode-long-k-float16`) and **9 of 15** are at or above `1.0`.

`ratio = native / TileOPs`; only a ratio above 1 means faster than that native baseline.
The pinned comparison snapshot (`yyttt6/TileOPs.github.io@63c58f47`, frozen 2026-11-16)
retains historical `ascend950-isolated-ffts-v2` rows for `ops-nn` / `ops-transformer`
explicitly labeled with their original protocol; merge qualification here uses the
same-process `ascend950-marker-session-v4` native comparison (450 raw profiler windows
replayed). The structural, contract, and boundary regression suite passes **163 tests,
zero skips** (`tests/test_ascend_gemm_w4a16_pipeline.py` + `tests/test_gemm_w4a16_workload.py`).

## Implementation

- **Group-paired nibble packing (`K >= 512, K % 256 == 0`)**: On Ascend NPU,
  `AscendW4A16RepackKernel` (`GEMMW4A16FwdOp.repack`) packs group `2p` at `k = b` into the
  low nibble and group `2p + 1` at `k = b` into the high nibble of byte `b` within each
  256-value K pair, while preserving the shared 64-byte Marlin packing on CPU/CUDA and on
  shorter or unpaired reductions (`K < 512` or `K % 256 != 0`).
- **Single-pass SIMD unpack & exact `uint8` zero point**: After `vintlv(low, high)`, group
  `2p` occupies the even byte lanes and group `2p + 1` the odd byte lanes, so widening
  `vcvt(uint8 -> float16, part=0/1)` extracts each complete 128-value group directly in
  natural K order without `vunpack` or an activation-permutation launch, and subtracting
  widened `uint8` zero points in `float16` preserves exact `[0, 255]` semantics without
  8-bit signed wraparound.
- **Producer/Cube pipeline & metadata streaming**: Disjoint AIV producers unpack into
  compact-NZ tiles while Cube contracts the preceding K tile (2 or 3 stages as UB/L1
  permits). Group metadata stays resident in UB when the full grid fits; otherwise two
  group columns stream per 256-wide K step. Non-power-of-two `N` shapes step down through
  valid 16-row divisors of `N` when fitting `tile_k = 256`.
- **On-chip resident K schedule**: Contractions whose entire K fits on chip (`w4a16_resident`)
  decode paired nibbles directly in natural K order when `K >= 512` (`K % 256 == 0`) and
  use the inverse-gather path on shorter or unpaired reductions.

## Measurement and provenance

- Physical device: `Ascend950DT_9582`, **32 Cube / 64 Vector**, `platform-default` clocks.
- Runtime: `torch 2.13.0+cpu`, `torch_npu 2.13.0.rc1`.
- Protocol: `ascend950-marker-session-v4`, fixed alternating provider order in the same process,
  **3 warmups + 15 profiler windows**, 1 GiB flush + sync per window, 450 raw windows replayed.
- Correctness: `final-profile-repeat` checks the final timed output of both providers against
  the independent FP32 reference and verifies input preservation.
- Guard: host `npu-guard` (`exit_code = 0`, `performance_valid = true`, `conflict_detected = false`).
- Kernel SHA256: `w4a16.py` `66ed5f3df575614606194785e71bb3fec6087d3701f147f399f74d1331dd4754`, `w4a16_resident.py` `695bdd3ef374af823a23677f22c1b2345cc6b4289d52950c5a21ba5f8e6de8e5`.
