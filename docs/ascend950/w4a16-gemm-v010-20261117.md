# W4A16 GEMM performance follow-up — 2026-11-17

## Result and qualification

The final integrated implementation passes all **15 manifest cases**, with full-output
verification, original numerical tolerances, negative controls, and input preservation.
Against the **same-process vendor contract** the PR block was raised on —
`torch_npu.npu_weight_quant_batchmatmul` with the identical packed weight, scales, zero
points and group size — all **15 ratios are at least 0.8**; the minimum is **0.854**
(`decode-hbm-streaming-float16`).

`ratio = vendor / TileOPs`; only a ratio above 1 means faster than that reference. The
pinned comparison snapshot (`yyttt6/TileOPs.github.io@63c58f47`, frozen 2026-11-16)
still carries `ascend950-isolated-ffts-v2` rows for `ops-nn` / `ops-transformer` that
report about 10 ms for every shape — flat across M, implying roughly 2.7 GB/s — and
those rows are **not** used here: this report stands on the same-process vendor
comparison, as the PR review requires. No case with a ratio below 1 is advertised as a
vendor-library speedup.

These are development-machine results, **not a replacement for canonical PR CI or
maintainer baseline qualification**. Each case also verifies the final timed output
against its reference outside the timing window in the same run. The structural and
boundary regression suite (this kernel's pipeline constraints plus the existing
quantization and repack contracts) passes **156 tests, zero skips**.

## Implementation

- Disjoint AIV producers unpack the packed nibbles directly into compact-NZ tiles in UB
  while the Cube contracts the preceding K tile. The block's vector sub-cores own a
  fixed producer role — one or two per block, by column width — so unpack work stays
  out of the Cube's critical path.
- Group metadata (scale and zero) stays resident in UB when the complete grid fits
  beside both staged operand tiles; otherwise exactly one group is staged per step.
- Quantization groups are paired into a 256-wide K tile whenever the resident metadata
  grid still fits. One producer round then feeds two 128-value groups, halving the
  producer loop count and the packed/B copy volume per contraction step. The pair is a
  resource-derived switch, not a case-ID or shape dispatch; a forced pair that cannot
  hold the metadata grid is refused instead of silently streamed one group at a time.
- When the whole contraction's K fits on chip, the resident schedule loads and
  dequantizes each output tile's weight once, restores the original activation order
  with an in-UB gather, and issues a single CV handoff. When it does not, the cheaper
  activation operand is permuted once by a 64-core vector kernel before the fused
  product.
- Public arguments and weight formats do not change: `AscendW4A16RepackKernel` still
  produces the same group-local order the GEMM reads, and the op contract
  (`GEMMW4A16FwdOp`) keeps its packed weight, scale, zero-point and group-size inputs.

## Measurement and evidence

- Physical device: `Ascend950DT_9582`, **32 Cube / 64 Vector**, normal platform clocks.
- Timer: the shared nightly raw-profiler timer — **3 warmups + 15 independent profiler
  windows**, 1 GiB eviction, no event/wall-clock fallback or sample trimming.
- Correctness: each case checks the final measured output outside timing with the
  existing `final-profile-output-v1` helper; the timer makes exactly 19 calls.
- Device discipline: every batch runs under the host NPU reservation
  (`npu_guard_transport` lease), acquired on a clean idle device and released after a
  final idle probe. Candidate and vendor run in the same process, same inputs, in the
  same lease.
- Kernel SHA256: `17531f33c240a6990356489104d0fc05decf343de605ae5a1c9142571761fb0c`.
- Raw profiles, per-case plans, correctness receipts and the driver log are retained at
  `/root/wt/pr83-perf-20261117/evidence/perf/` on the development host.

## Rejected attempts and infrastructure findings

- A resident-activation variant (whole A tile in L1 for the fused schedule) reached
  49.8 µs on `llama-8b-decode-down` where the vendor is 39.8 µs — still below the 0.8
  ratio; rejected. Pairing the quantization groups is what cleared that case (35.3 µs).
- Dropping the redundant high-nibble mask (`vand` after a logical `vshrs` by 4) measured
  49.08 µs on `llama-8b-decode-down` in its own guarded run, against 50.01 µs for the
  same pre-pairing kernel in the preceding batch — a 1.9 % difference, comparable to the
  run-to-run spread. It was not carried into the final schedule; the pairing change
  superseded it and the final numbers above are measured without it.
- The `ascend950-isolated-ffts-v2` baseline rows implied a roughly 140–310× gap that no
  same-process measurement reproduced; the findings were reported in issue #88/#90 and
  are not repeated as evidence here.
