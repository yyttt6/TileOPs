## Implementation

- Broadcast one FP16-rounded scale per 128-element group using the public SIMD API,
  rather than loading it independently for every element. Both scale rounding and
  operand-fold arithmetic remain unchanged for the multirow path.
- Batch short operand rows only when both buffer versions fit within the existing
  176 KiB UB budget and the 64 AIVs retain enough work to fill the two-stage pipeline.
  This is a resource/work-granularity rule, not a case-ID or fixed-shape dispatch.
- For a one-row contraction, stream FP8 operands and FP32 scale grids in one vector
  launch when the resident activation and staged weight rows fit UB. Retain the
  existing Cube path when they do not. Public arguments and weight formats do not change.
- Scale both operands before multiplying, matching the reference's FP32 intermediate
  order. Regression inputs include finite extreme scales where reassociation overflows.
- Store scalar FP32 reductions with `ONEPT_B32`, then cast the contiguous output tile;
  packed narrow vector stores cannot address arbitrary row offsets safely.

The multirow block-scale implementation retains its original FP16-folding precision
regime; this change does not establish a new guarantee over the entire FP32 scale
value domain. Its published workload samples scales in `[0.5, 1.5]`. The new single-row
path explicitly checks the additional extreme-scale cases in the regression suite.

## Rejected attempts and infrastructure findings

- MXFP8 approximation rounded arbitrary FP32 scales to powers of two and produced
  invalid outputs: rejected, not used as a silent fallback.
- High-level SIMD FP8 cast lowering was unsupported by the pinned compiler; the
  implementation uses its existing public vector-conversion API, with no compiler patch.
- Dynamically indexed arrays of vector registers failed device compilation; streaming
  the activation from UB removed that requirement.
- An early GEMV packed-store variant raised an unaligned-UB exception; fixed at the
  reduction/output boundary before any candidate was promoted.
- A four-row fold left the short-K prefill case at approximately 443 µs, below the
  required ratio. Resource-bounded row batching reduced it to approximately 413 µs.
- Fresh SSH connections created nondumpable `sshd: [net]` sandbox processes that the
  container could not inspect. The guard correctly rejected those runs. A persistent
  SSH connection eliminates self-inflicted handshakes; unknown external visibility
  failures remain fatal. No daemon-name whitelist was added.
- Private cooperative-lock acquisition uses a bounded blocking flock to avoid polling
  starvation. Four real lock tests and sixteen process-visibility/contamination tests
  pass. The shared site guard and other users' reservations remain untouched.
